# territoreando-space — Flame in Freefall

**SAFFIRE-II evidence explorer** for the NASA Space Apps Challenge 2026 challenge
*Flame in Freefall: AI-Powered Fire Safety Insights from Microgravity Combustion Data*.

## What this is
A visual dashboard over NASA's Saffire-II microgravity combustion data (flown on Cygnus CRS OA-5). It lets anyone —
students, developers, people without aerospace training — browse the released image sequences, check whether each
one is temporally continuous, play them frame by frame with full traceability (sequence, frame, `raw_id`, time,
source file), plot simple pixel statistics, and read published scientific results next to them.

> Evidence-exploration dashboard. Not a CFD solver, not a fire-risk predictor, not a digital twin.

## What to consider before contributing
1. **Raw data is not in Git.** The SAFFIRE-II images, archives, inventory and paper (~2.4 GB) are ignored by
   `.gitignore`. Ask the maintainers for `SAFIRE-II Project.zip` (team shared storage) and unzip it in the repo root so `./descompressed/`
   exists. The generated catalogs in `data/processed/` *are* committed, so the catalog views work without images.
2. **Scientific honesty is a feature.** Never show temperature, heat-release rate, oxygen, fire risk, or lengths in
   mm/cm derived from pixels. Never assign a folder label (S1…S9, F1, F2) to a Saffire-2 sample number or material.
   Every scientific statement needs a source (file + page). See [docs/scientific-limitations.md](docs/scientific-limitations.md).
3. **Never merge variants.** Raw, Mapped, ICMAD and TIFF versions of the same time window are separate sequences.
4. **Original files are read-only.** Everything derived is regenerated by `pipeline/`.
5. **Branching.** Work on `development` (or feature branches from it); `main` is for reviewed releases.
6. **Working with AI agents.** [AGENTS.md](AGENTS.md) is the single source of truth for architecture, commands and
   rules; `CLAUDE.md` imports it. Point any coding agent at it before asking for changes.
7. **Challenge requirements.** The official deliverable list is published on 28 Oct 2026; nothing here assumes it.

## Layout
```
descompressed/        original NASA files (read-only; not modified)
pipeline/             build_catalog.py, compute_metrics.py
data/processed/       generated catalogs and metrics (CSV)
data/scientific_reference_results.json   values transcribed from urban2019.pdf (with pages)
backend/              FastAPI app + deterministic assistant
frontend/             React + TypeScript + Vite + Tailwind
tests/                pytest suite
docs/                 context, data dictionary, lineage, limitations, demo script, plan
AGENTS.md             architecture + rules for AI coding agents (CLAUDE.md imports it)
```

## Requirements
Python 3.11+ with [uv](https://docs.astral.sh/uv/), Node 20+.

## Data paths
Raw data is expected in `./descompressed/` (unzip `SAFIRE-II Project.zip` in the project root; it contains that folder). Override for the API with
`SAFFIRE_RAW_DIR=/path/to/descompressed`. Missing images do not crash anything: frames are marked `missing` /
`path_only` and the UI shows a warning.

## Build the data (≈15 s)
```bash
uv sync
uv run python -m pipeline.build_catalog --raw descompressed     # 21 sequences, 69,380 frames
uv run python -m pipeline.compute_metrics --raw descompressed   # every 5th frame (+ post-gap and last)
```

## Run
```bash
uv run uvicorn backend.app:app --port 8000          # API  → http://localhost:8000/docs
cd frontend && npm install && npm run dev           # UI   → http://localhost:5173
```
Deep link: `http://localhost:5173/#Viewer/S1-C2-raw-jpeg-part1`.

## Test & lint
```bash
uv run pytest -q
uv run ruff check pipeline backend tests
cd frontend && npm run lint && npm run build
```

## API
All responses: `{ "data", "source", "warnings", "quality" }`.

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | catalog status |
| `GET /api/investigations` | Saffire-II summary (from urban2019) |
| `GET /api/sequences` | list; filters `group, camera, file_type, processing_variant, temporal_quality` |
| `GET /api/sequences/{id}` | one sequence + warnings |
| `GET /api/sequences/{id}/frames?offset&limit&step` | frames |
| `GET /api/frames/{frame_id}` | frame detail + metrics |
| `GET /api/frames/{frame_id}/image` | image (TIFF converted to PNG) |
| `GET /api/calibrations` | distortion grids and status |
| `GET /api/sources` | source files and availability |
| `GET /api/metrics/{id}` | metric time series |
| `GET /api/references` | published reference values |
| `POST /api/assistant` | `{question, sequence_id?}` → Observation / Interpretation / Evidence / Limitations |

## Data limitations (short)
- `raw_id` is treated as milliseconds (inferred from ~33 ms spacing and 30 fps cameras, urban2019 p.173).
- S1…S9 / F1 / F2 / C1 / C2 are folder labels, not proven sample numbers or camera identities.
- Mapped TIFF series have gaps up to 183 s → unsuitable for rates.
- Raw / Mapped / ICMAD variants of the same window are separate sequences, never merged.
- Calibration is `pending`: all measurements in pixels.
- Green LED flashes and the TIFF text banner affect pixel metrics.

Full list: [docs/scientific-limitations.md](docs/scientific-limitations.md). Demo: [docs/demo-script.md](docs/demo-script.md).
